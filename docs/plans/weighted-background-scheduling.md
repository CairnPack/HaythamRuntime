# 后台任务的加权调度

## 要解决的问题

设了并发上限以后，用户手动发起的任务和后台任务（例如清理提醒的扫描）会争同一批名额。如果只是“后台任务排在后面”，用户任务一直不断时，后台任务可能永远轮不到。

## 目前的想法

这是 Astra 在评审文件第九轮提出的：

- 后台等级只表示“争用名额时优先级较低”，不抢占已经在运行的任务，也不改变同一排队键内的先后顺序。
- 正常任务和后台任务按权重选择，并保证一直有正常任务时，后台任务仍能获得执行机会。
- 权重是内部参数，不写进公开接口。
- 后台等级不用操作系统的线程优先级实现，因为一次任务会经过多个线程和 I/O 等待，线程优先级表达不了整个操作的优先级。需要限制后台下载速度时，在下载器那一层处理。

用户补充：并发上限主要针对用户手动发起的任务，后台任务应该作为被动并发单独考虑。拿出这个提案时，先决定后台任务是和用户任务共用一个上限、按权重分配，还是各自有一个上限。

## 为什么现在不做

它依赖[任务并发上限](task-concurrency-limits.md)。第一版不设上限，后台任务没有可争的名额，加权就没有作用。
