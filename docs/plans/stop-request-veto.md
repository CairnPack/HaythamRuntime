# OnStopRequested 的否决语义

## 要解决的问题

正式停止的第一步是派发 `OnStopRequested`，任何模块都可以调用 `e.Cancel()` 否决这次停止。但什么情况下真的需要否决，现在还没有想清楚。

用户指出：像“正在把一大批数据写进磁盘、中途不能停”这种情况，应该做成退出策略为 `Wait` 的任务，进入预退出后让它继续做完，而不是靠否决。所以否决应该留给 Runtime 看不到的状态，例如没有做成任务的东西。

## 已经暂定的部分

- 每个模块收到自己的事件对象，宿主最后汇总是哪些模块否决了。
- 订阅者在判定时抛异常（评审文件 4.1）：暂定本次停止失败，返回 `DecisionFailed` 和错误，Runtime 恢复运行。

## 拿出来时要做的事

- 定下 `OnStopRequested` 的否决和预退出（`PreStopAsync`）怎样分工。
- 回头检查 4.1 的暂定答案，以及 Astra 在评审文件第一轮第 7 节给出的方案，能不能沿用。
