# 按条件订阅：OnSubscribing 阶段

## 要解决的问题

现在模块在 `OnRegistering` 里同时登记自己的 Task、事件和订阅。`Subscribe` 只是把订阅记下来，所有模块都登记完以后才统一检查订阅的事件有没有人登记，所以登记和订阅之间不需要固定的先后顺序。

这个设计处理不了一种情况：订阅者要根据“某个事件这次有没有被登记”来决定要不要订阅。例如“如果有模块提供了 CAS 相关的事件，我就订阅它；没有就算了”。

## 目前的想法

在 `OnRegistering` 和第二次锁定之间加一个 `OnSubscribing` 阶段：

1. `OnRegistering`：各模块只登记自己提供的 Task 和事件。
2. 锁定 Task 和事件的定义。
3. `OnSubscribing`：各模块可以查询有哪些事件被登记了，再决定订阅什么。
4. 第二次锁定：锁定订阅关系。

## 为什么现在不做

目前没有按条件订阅的需求。加这个阶段会多一次锁定，启动步骤也会变多。出现具体场景时再做。
